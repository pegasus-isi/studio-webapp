02 · The load-bearing part

Chat-driven only works if replies are operable

This is the piece that decides whether the thesis holds. If the assistant answers in prose and then tells you to go to another screen and press something, chat is a help desk with extra steps. Every reply that produced or changed an object has to return that object, with its real controls attached and its real state on it.

03 · Analyses

The graph gets the screen. Parameters get a drawer.

Today the parameter form owns a permanent third of the width and the graph is squeezed into what is left. Inverting that is right — you look at the graph constantly and touch the parameters twice per run. But a bigger canvas only helps if what is on it is readable, and a 167-way scatter drawn as 167 nodes is not. Clustering is what makes the canvas worth enlarging.

04 · Navigation

Keep the icon rail. Add nine-pixel labels.

I argued against the icon rail last round. That was the wrong call — the dashboard read is worth having and it is what the rail buys. The one thing worth fixing is that unlabeled icons are a memory test on first use, and that costs nothing to solve: a 68px rail fits a micro-label under each icon and still reads as a rail, not a sidebar.

What changed from revision 1

  • Landing is now the chat, full size. State moved into the assistant's opening turn instead of sitting beside it.
  • Graph before parameters on the analyses screen; the form became a slide-over and kept all of its fixes.
  • Icon rail adopted. I argued against it last round and was wrong — the amendment is a 9px label, not a different pattern.
  • Palette swapped to the captures' cornflower system, with the filled-action step darkened to clear AA.

What this direction costs

  • Chat-driven is mostly backend. Operable replies need assistant tools that return typed objects, plus a renderer per object type in the client. That is the real work in plate 02, not the layout.
  • Undo has to be real. Once the assistant submits, registers and retries on your behalf, every card action needs a reversal path.
  • The vocabulary gate still stands. docs/ux-terminology-test.md is written and unrun, and this revision adds new words — "Assistant", "Compute", "Analyses".
